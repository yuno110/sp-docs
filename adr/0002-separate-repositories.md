# 0002. 저장소 분리와 문서 전용 저장소

## 상태
accepted

## 맥락

서비스를 단일 저장소(monorepo)에 둘지, 저장소를 나눌지 정해야 했다. 초기 검토에서는 1인 개발 규모를 근거로 단일 저장소를 권장했다.

> **2026-09-15**: auth 분리로 코드 저장소가 셋이 됐다([0012](0012-auth-as-separate-service.md)). 아래의 "두 서비스"는 `sp-auth`·`sp-member`·`sp-board` **셋**으로 읽는다. 결정 자체는 바뀌지 않았고 비용(계약 조율, `AGENTS.md` 복제)만 한 벌 늘었다.

## 결정

**서비스별 저장소로 분리한다.** 문서는 별도의 문서 전용 저장소에 둔다.

| 저장소 | 내용 |
| --- | --- |
| `yuno110/sp-member` | member-service 코드 + `docs/checklist.md` |
| `yuno110/sp-board` | board-service 코드 + `docs/checklist.md` |
| `yuno110/sp-docs` | 정본 문서, 작업 계획 |

## 근거

- 사용자가 이미 두 저장소를 생성하고 푸시했다. 실제 운영 환경에 가까운 구성이다
- MSA의 독립 배포 원칙과 저장소 경계가 일치한다
- **워커 병렬 작업에 유리하다.** member 워커와 board 워커가 서로 다른 저장소에서 작업하므로 충돌 지점이 없다

문서를 별도 저장소로 둔 이유:
- 모든 서비스가 정본을 대칭으로 참조할 수 있다. 어느 한쪽에 두면 비대칭이 생긴다
- 두 저장소에 복제하면 코드 복제와 같은 동기화 문제가 문서에 생긴다
- 문서 저장소는 빌드·배포 파이프라인이 없어 추가 비용이 사실상 0이다

## 결과

- 작업 상태(`checklist.md`)를 한 곳에 모을 수 없게 되었다. **항목별로 원본을 하나로 두는 방식**으로 해결한다. M-xx 상태는 member 저장소, B-xx 상태는 board 저장소에 있다([../plan/README.md](../plan/README.md))
- 두 서비스에 걸친 변경(예: JWT Claim 스펙)을 한 커밋으로 묶을 수 없다. 계약 지점을 문서에 먼저 확정하고 각 저장소가 따르는 방식으로 대응한다([../api-contract.md §6](../api-contract.md))
- `AGENTS.md`를 저장소마다 복제해야 한다. 프로젝트 무관한 행동 원칙이라 거의 바뀌지 않아 비용이 낮다

> **사본이 더 생겼다** — 2026-10-18 (D-04) 과 2026-10-20 (D-09) 이 각각 하나를 더했다. 전자는 `D-xx` 를 하는 워커만 불변식 문서 없이 일하고 있었기 때문이고, 후자는 프론트엔드가 제품 범위로 올라왔기 때문이다.
>
> **모든 사본을 바이트 동일로 유지한다. 한쪽을 고치면 나머지를 고친다.** **어느 저장소가 사본을 갖는지도, 몇 개인지도 적지 않는다** — `AGENTS.md` 자신의 머리글이 저장소를 열거했다가 거짓이 됐다([../plan/phase1.md](../plan/phase1.md) D-09). 사본을 찾는 방법은 **세는 것이 아니라 보는 것이다**: 저장소마다 루트에 있다.
>
> **해시도 적지 않는다.** 앞 판이 md5 를 박아 뒀는데 **지금은 어느 사본과도 맞지 않는다.** D-04 가 틀린 값을 적은 것이 아니다 — **그 값은 당시 작업 트리(CRLF)의 해시로 정확했고, `D-07` 의 줄끝 고정이 그것을 무효로 만들었다**(실측: 기록된 값은 당시 blob 내용의 CRLF 판과 일치하고, blob 자체의 해시는 다른 값이다). **정확하게 적어도 낡는 종류라는 것이 요점이다.** 일치는 `md5sum` 으로 **그때 재서** 확인한다.
>
> **`sp-docs` 안에서는 `AGENTS.md` 로 가리킨다**(루트 문서) 또는 `../AGENTS.md`(`plan/`·`process/` 안). D-04 전에는 루트 문서 다섯이 `../AGENTS.md` 로 적어 **저장소 바깥**을 가리켰다 — 파일을 만드는 것만으로는 그 다섯이 참이 되지 않았다(실측).
- 워커가 저장소 2~3개를 봐야 한다. 문서 저장소는 읽기 전용이라 부담이 작다

## 재검토 조건

두 서비스에 걸친 변경이 잦아 계약 조율 비용이 커지면 단일 저장소를 재검토한다.
